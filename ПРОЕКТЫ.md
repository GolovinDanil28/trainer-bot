# Реестр проектов

Четыре трека. Каждый — отдельный продукт, но **все четыре тренируют одну и ту же
методику**: спека → реализация → ревью → ретро.

Источник: срез сессии OpenCode Desktop от 19.10.2026
(«Какие модели Ollama подходят для локального запуска»).

---

## 1. Тренер-напоминалка (Telegram-бот) — `projects/trainer-bot`

**Статус:** стартуем сейчас. Структура уже придумана в предыдущей сессии.

**Что делает:**
- напоминает о тренировках и привычках;
- отслеживает прогресс;
- корректирует план по самочувствию (пользователь отвечает «как себя чувствую»
  → план на день/неделю меняется).

**Скоуп v1 (чтобы было что показать за 2 недели):**
- одно расписание (расписание тренировок);
- ежедневные напоминания в заданное время;
- отметка «выполнил / пропустил»;
- журнал выполнения с историей;
- вечерний чек-ин самочувствия (1–5) → план на завтра корректируется.

**Скоуп v2 (после v1):** адаптивная нагрузка, недельные сводки, экспорт в CSV,
интеграция с календарём.

**Почему первым:** самый короткий цикл обратной связи (команда → код → проверка
на телефоне), и в нём есть ровно все механики, которые потом понадобятся в
остальных треках: расписание, состояние, диалог с пользователем, хранение
данных, деплой.

**Стек (предложение, требует твоего утверждения):**
- Python 3.14 + `python-telegram-bot` (или aiogram — выбрать);
- SQLite + SQLAlchemy (или Tortoise ORM);
- APScheduler для расписаний;
- Docker для локального запуска, systemd/launchd или VPS для прода;
- pytest.

## 2. Изучение английского — `projects/english`

**Статус:** второй. Реализовывать **на тех же кишках**, что и trainer-bot.

**Зачем отдельный проект, если есть тренажёр по Python:**
- это другой тип обратной связи — не «задачка → решение», а «карточка →
  запоминание → интервальное повторение»;
- даёт второй пример интерфейса бота без новой архитектуры;
- тренирует работу с контентом и расписанием повторений (SRS-алгоритм).

**Скоуп v1:** колода карточек, режим «сессия на 10 минут», оценка ответа
(1–5), алгоритм интервального повторения (SM-2 или FSRS), статистика.

**Скоуп v2:** генерация карточек из своих текстов, разговорный режим
(voice → распознавание → оценка произношения), Word/Article-уровень.

## 3. Тренажёр по Python — `projects/python-trainer`

**Статус:** третий.

**Формат:** задачи в стиле Leetcode — условие, ввод, вывод, проверка.

**Скоуп v1:** банк из 30–50 задач с автотестами, категории (строки, списки,
словари, алгоритмы), подсказки в три уровня, разбор решения.

**Скоуп v2:** рейтинг и серии (streak), разбор кода пользователя (использует
LLM), режим «собеседование».

**Чем ценен:** первое место, где агент-ревьюер реально нужен — проверить
идиоматичность и стиль чужого кода.

## 4. Обучение AI Engineering — `projects/ai-engineering`

**Статус:** параллельный трек, идущий **всю дорогу**, а не после.

**Важно:** это не «проект, который делают», а «трек, на котором ты учишься
работать с ИИ». Материал — то, что мы делаем в остальных трёх: агенты,
скиллы, хуки, харнесс, OpenSpec, RAG.

**Скоуп (не код, а артефакты):**
- `knowledge/` — корпус заметок по темам трека;
- по одной «учебной артефактуре» на неделю: свой скилл, свой хук, свой
  сабагент, свой RAG-индекс;
- журнал в `learning/LOG.md` — что понял, что нет.

**Темы:** агенты и оркестрация, harness-подходы, спецификация как контракт,
память и RAG, инструменты (MCP), evals, работа с локальными моделями
(Ollama), стоимость и лимиты.

## Как пользоваться реестром

1. Активный проект — **один**. Не распыляйся.
2. Смена проекта — только через `/retro` с записью, чем закончили предыдущий.
3. Трек №4 идёт параллельно: раз в неделю одна учебная артефактура.
4. Любая функциональность любого проекта проходит через OpenSpec-спеку.
