# Spec Delta — trainer-bot-users

## Purpose

Один бот — несколько людей, у каждого свои тренировки, самочувствие и планы.
Чужое не видно и не меняется.

## ADDED Requirements

### Requirement: R-41 Учётная запись пользователя
Система SHALL хранить пользователя с telegram id, таймзоной, временем вечернего
вопроса, временем недельного разбора и признаком активности. Владелец из
`OWNER_ID` SHALL создаваться автоматически и идемпотентно при старте. Пользователь
без учётной записи SHALL получать отказ, а не данные бота.

#### Scenario: Владелец создаётся при старте
- **WHEN** бот запускается с `OWNER_ID`, которого ещё нет в базе
- **THEN** создаётся пользователь с таймзоной и временами из настроек

#### Scenario: Повторный старт не дублирует
- **WHEN** бот запускается второй раз с тем же `OWNER_ID`
- **THEN** у пользователя по-прежнему одна строка, настройки не сбрасываются

#### Scenario: Незарегистрированный получает отказ
- **WHEN** сообщение приходит от telegram id, которого нет в базе
- **THEN** бот отвечает отказом и не показывает тренировки, самочувствие или планы

### Requirement: R-42 Изоляция данных пользователей
Система SHALL привязывать тренировки, самочувствие, снимки планов и недельные
отчёты к пользователю. Команды SHALL показывать и менять только строки текущего
пользователя; обращение к чужой строке SHALL выглядеть как обращение к
несуществующей.

#### Scenario: Список тренировок
- **WHEN** у двух пользователей есть тренировки
- **THEN** `/list` каждого показывает только его тренировки

#### Scenario: Чужая тренировка не отключается
- **WHEN** пользователь отправляет `/off` с номером чужой тренировки
- **THEN** бот отвечает «тренировка не найдена», чужая остаётся активной

#### Scenario: Самочувствие за один день
- **WHEN** два пользователя отвечают на вопрос за одну и ту же дату
- **THEN** в базе две строки — по одной на пользователя, оценки не перетираются

#### Scenario: Снимки и разборы
- **WHEN** два пользователя получают план на одну дату
- **THEN** снимков два; `/week` каждого строится только по его снимкам

#### Scenario: Свободный текст видит только своё
- **WHEN** пользователь пишет «покажи расписание», а у второго есть тренировки
- **THEN** в снапшот для модели и в ответ попадают только свои тренировки

### Requirement: R-43 Миграция существующей базы
Система SHALL переносить данные старой базы на пользователя без потерь:
число строк каждой таблицы до и после миграции SHALL совпадать, а все
тренировки, самочувствие, снимки и недельные отчёты SHALL получить владельца.
Перед миграцией SHALL сниматься копия файла базы; при любом сбое база SHALL
восстанавливаться из копии. После переноса число строк каждой таблицы SHALL
сверяться с исходным. Повторный запуск SHALL быть безопасным.

#### Scenario: Данные сохраняются
- **WHEN** база прошлого релиза содержит тренировки, расписание, напоминания,
  отметки, самочувствие, снимки плана и недельный отчёт
- **THEN** после старта число строк каждой таблицы совпадает, у владельца
  появились его данные

#### Scenario: Строка без момента права
- **WHEN** в старом недельном отчёте момент взятия права (`claimed_at`) пуст
  или такой колонки ещё нет
- **THEN** миграция проходит, а строка получает непустой момент

#### Scenario: Сбой не теряет данные
- **WHEN** миграция падает на середине
- **THEN** транзакция откатывается, старая база остаётся в прежнем состоянии

#### Scenario: Повторный старт
- **WHEN** бот запускается второй раз после миграции
- **THEN** данные и владелец не дублируются, настройки не сбрасываются
