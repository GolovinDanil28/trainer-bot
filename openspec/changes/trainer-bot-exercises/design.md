# Design: trainer-bot-exercises

### D1. Курируемый справочник, а не модель

Упражнения — статический набор в коде: его можно объяснить, проверить и
изменить. Модель, придумывающая упражнения, ошибается незаметно и может
навредить; для бота без тренера это недопустимо.

### D2. Семейство по корню типа

«силовая», «жим», «приседания» → силовая; «бег», «интервальный бег», «вело» →
кардио; «растяжка», «йога», «мобильность» → мобильность. Незнакомое — без
блока: пустота честнее выдумки.

### D3. Фаза от первой тренировки семейства

Дата создания первой активной тренировки семейства — якорь. Недели считаются
в зоне пользователя. 8 недель = 4 фазы по 2; после — цикл заново с пометкой.
Отдельного поля «старт программы» не заводим: расписание и есть программа.

### D4. Один блок на семейство

Если в расписании три силовые, блок один: упражнения зависят от семейства и
фазы, а не от числа тренировок. Иначе совет распухнет и повторится.

## Risks

- **[Травма]** → пометка «не медицинская рекомендация», простые упражнения,
  без весов и нормативов.
- **[Смена типа сбрасывает фазу]** → якорь — первая тренировка семейства;
  переименование типа в то же семейство фазу не сбрасывает.
- **[Удаление всех тренировок семейства]** → блока нет; после создания новой
  цикл начнётся с первой фазы.
