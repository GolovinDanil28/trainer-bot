# Proposal: trainer-bot-duration

## Why

Длительность недельной тренировки сейчас не задать: `/new` берёт её по типу
(силовая 45, кардио 30, мобильность 20) или считает из дистанции. «Бег 40 минут
по средам» сказать нельзя — получится 30 по умолчанию.

Свободный текст при этом **уже умеет** длительность: модель отдаёт
`duration_min`, и `AssistantService` передаёт его в создание. То есть два пути
создания расходятся: фразой можно, командой нельзя.

## What Changes

- `/new` принимает необязательный четвёртый аргумент — минуты:
  `/new бег Пн,Ср,Пт 19:30 40`.
- Допустимый диапазон 5–600 минут; вне его — ошибка без записи в базу.
- Без аргумента всё как раньше: длительность по типу, из дистанции или 30 минут
  для свободного типа.
- Карточка и README показывают пример с длительностью.

## Impact

- `src/core/schedule.py`: `parse_new_command` (необязательный аргумент),
  границы проверки.
- `src/core/messages.py`: пример в ошибках `/new`.
- `src/core/help.py`, `README.md`: пример команды.
- Тесты: парсер, сервис, карточка.

## Modified Capabilities

- `trainer-bot-schedule`: R-01 — необязательная длительность в `/new`.

## Оценка

1,5–2 часа. Не зависит от других изменений.
