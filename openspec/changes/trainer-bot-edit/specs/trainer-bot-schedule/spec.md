# Spec Delta — trainer-bot-schedule

## ADDED Requirements

### Requirement: R-48 Редактирование тренировки
Система SHALL менять у существующей тренировки тип, дни недели, дату разовой
или время командой `/edit <номер> <поле> <значение>`, сохраняя её id,
длительность и дистанцию. Поля: `type`, `days`, `date`, `time`. При смене дней,
даты или времени неотправленные напоминания старого расписания SHALL
отменяться. Дни SHALL приниматься только у недельной тренировки, дата — только
у разовой. Ошибка SHALL NOT менять данные.

#### Scenario: Смена типа
- **WHEN** пользователь отправляет `/edit 2 type бег`
- **THEN** тип тренировки №2 — «бег», время, дни и длительность те же

#### Scenario: Смена дней
- **WHEN** пользователь отправляет `/edit 2 days Пн,Ср`
- **THEN** тренировка №2 напоминает по понедельникам и средам в прежнее время

#### Scenario: Перенос разовой на дату
- **WHEN** пользователь отправляет `/edit 3 date 07.11`
- **THEN** разовая тренировка №3 переносится на 7 ноября, время то же

#### Scenario: Дата в прошлом
- **WHEN** пользователь указывает дату с прошедшим годом
- **THEN** бот отвечает ошибкой, дата не меняется

#### Scenario: Дни у разовой
- **WHEN** пользователь отправляет `/edit 3 days Пн` для разовой тренировки
- **THEN** бот отвечает ошибкой, данные не меняются

#### Scenario: Дата у недельной
- **WHEN** пользователь отправляет `/edit 2 date 07.11` для недельной
- **THEN** бот отвечает ошибкой, данные не меняются

#### Scenario: Время как у /move
- **WHEN** пользователь отправляет `/edit 2 time 20:00`
- **THEN** результат совпадает с `/move 2 20:00`

#### Scenario: Чужая тренировка
- **WHEN** пользователь редактирует тренировку другого человека
- **THEN** для него она «не найдена», чужие данные не меняются

#### Scenario: Старые напоминания отменены
- **WHEN** у тренировки были неотправленные напоминания старого расписания
- **THEN** после смены дней/даты/времени они не отправляются
