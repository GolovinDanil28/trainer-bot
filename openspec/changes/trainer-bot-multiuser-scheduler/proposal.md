# Proposal: trainer-bot-multiuser-scheduler

## Why

Фундамент нескольких пользователей готов: данные изолированы, владелец
создаётся из `OWNER_ID`. Но войти второму человеку нельзя, а планировщик
обслуживает только пользователя по умолчанию: напоминания, вечерний вопрос и
недельный разбор приходят одному, по его таймзоне и временам из конфига.

Этот change открывает вход и делает тики многопользовательскими.

## What Changes

- Регистрация по `/start <код>`: один общий многоразовый код из `INVITE_CODE`.
  Неверный или отключённый код не создаёт пользователя.
- При регистрации человек получает таймзону и времена вопроса/разбора из
  настроек; своей команды настроек пока нет (решение владельца).
- Планировщик обходит всех активных пользователей: каждому — своё расписание,
  своя таймзона, своё время вопроса и разбора, свой чат.
- Напоминание уходит владельцу тренировки; `/start` зарегистрированного
  по-прежнему показывает карточку.
- `is_active=false` исключает пользователя из тиков и доступа.

## Impact

- `src/config.py`: `INVITE_CODE` (опционально), валидация.
- `src/bot/access.py`: регистрация в `/start` до проверки доступа.
- `src/db/repository.py`: создание пользователя, список активных.
- `src/scheduler/*`: обход пользователей, отправители и зоны на пользователя.
- `src/app.py`, `src/bot/handlers.py`, `src/bot/telegram_sender.py`.
- `.env.example`, README, карточка (`/start` для незарегистрированного).

## Modified Capabilities

- `trainer-bot-users`: MODIFIED R-41 (активность и исключение для регистрации),
  ADDED R-44 (регистрация по коду).
- `trainer-bot-delivery`: R-06 — напоминание владельцу тренировки.
- `trainer-bot-wellness`: R-19 — время вопроса из учётной записи.
- `trainer-bot-plan`: R-40 — разбор каждому по его времени.
