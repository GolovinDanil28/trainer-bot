# Design: trainer-bot-multiuser-scheduler

### D1. Один общий код, сравнение без утечки времени

`INVITE_CODE` — многоразовый код в `.env`. Пустое значение отключает
регистрацию: личный бот остаётся личным, пока владелец не решит иначе.
Сравнение — `hmac.compare_digest`: код нельзя подбирать по времени ответа.
Одноразовые коды и учёт выдач — отдельный change, здесь не нужны.

### D2. Регистрация только через `/start <код>`

`/start` — единственная команда без `registered_only`. Код разбирает
`UserService`, а не хендлер: правило входа не должно зависеть от того, какой
хендлер его вызвал. Свободный текст от незарегистрированного остаётся отказом —
код не уходит в модель и не ищется в тексте.

### D3. Тики обходят активных пользователей

`MultiUserJobs` для каждого активного пользователя собирает свой тик:
- отправитель привязан к `telegram_id` (личный чат);
- зона — из `user.tz`;
- время вопроса и разбора — из строк пользователя;
- `acting_as(user.id)` выставляет владельца, и репозиторий фильтрует данные.

Сбой у одного пользователя ловится и логируется: недоступный чат не должен
глушить напоминания остальным.

### D4. `scheduler/` не знает про Telegram

`JobFactories` принимает функции, а не классы: `app.py` создаёт
`TelegramSender`/`TelegramWellnessSender`/`TelegramReportSender` на пользователя.
Правило §8.1 сохраняется: планировщик работает с портами, транспорт — в `bot/`.

### D5. Настройки — копия из `.env` при регистрации

`/settings` отложен: при регистрации в строку копируются `TZ`,
`WELLNESS_TIME`, `WEEK_REVIEW_TIME`. Менять их потом — только правкой базы;
это осознанное упрощение, записано в README. Когда появится `/settings`,
сервисы должны будут брать зону из профиля, а не из настроек процесса.

### D6. `is_active=false` — полноценный выключатель

Пользователь с `is_active=false` не проходит доступ и не попадает в обход
тиков. Так владелец может «заморозить» человека, не удаляя его данные.

## Risks

- **[Код утёк]** → смена `INVITE_CODE` + рестарт; старые учётки остаются.
- **[Разные TZ при общих сервисах]** → пока все получают `TZ` из `.env`,
  сервисы с глобальной зоной корректны; `/settings` потребует зону из профиля.
- **[Один пользователь ломает тик]** → изоляция по пользователю и лог с id,
  остальные продолжают.
- **[Личные данные в чужом чате]** → отправитель создаётся на пользователя;
  тест «два пользователя — два сообщения» обязателен.
