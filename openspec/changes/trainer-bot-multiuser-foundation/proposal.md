# Proposal: trainer-bot-multiuser-foundation

## Why

Бот умеет работать только с одним человеком: владелец зашит в `OWNER_ID`, а все
данные лежат без владельца. Добавить второго человека нельзя не из-за кода
доступа, а из-за схемы: `wellness.day` уникален глобально, `plan_snapshot.plan_date`
тоже, `weekly_report.week_start` тоже. Второй пользователь просто не сможет
записать самочувствие за день, который уже есть у первого.

Этот change — фундамент: учётные записи и изоляция данных. Регистрация и
обслуживание нескольких пользователей планировщиком — следующие два change'а;
здесь сознательно не открываем вход новым людям.

## What Changes

- Новая сущность «пользователь»: telegram id, таймзона, время вечернего вопроса
  и недельного разбора, активность. Владелец из `OWNER_ID` создаётся
  автоматически при старте.
- У всех данных появляется владелец: тренировки, самочувствие, снимки планов,
  недельные отчёты. Расписания, напоминания и отметки наследуют владельца через
  тренировку — дублировать `user_id` в них не нужно.
- Все команды и свободный текст работают только со строками текущего
  пользователя; чужая тренировка для `/off` выглядит как несуществующая.
- Миграция существующей базы: старые строки становятся данными владельца,
  уникальные ограничения переезжают на пару «пользователь + дата».

## Impact

- `src/db/models.py`: таблица `user`, `user_id` в `workout`, `wellness`,
  `plan_snapshot`, `weekly_report`; уникальности — составные.
- `src/db/session.py`: миграция с пересозданием таблиц, где меняется
  UNIQUE-ограничение (SQLite не умеет менять ограничения через ALTER).
- `src/db/repository.py`: все выборки и записи фильтруются по владельцу.
- `src/bot/access.py`: `owner_only` → «только зарегистрированный», текущий
  пользователь — из обновления, а не из константы.
- `src/bot/service.py`, `wellness_service.py`, `assistant_service.py`,
  `handlers.py`, `callbacks.py`: операции принимают пользователя.
- `src/app.py`: создание/подхват пользователя при старте.
- Тесты: существующие получают пользователя-фикстуру; новые — на изоляцию.

## Modified Capabilities

- `trainer-bot-users` (новая): R-41 учётные записи, R-42 изоляция данных.
- `trainer-bot-assistant`: R-18 — свободный текст от зарегистрированного.
- `trainer-bot-wellness`: R-19 — вопрос раз в день **на пользователя**.
- `trainer-bot-plan`: R-36 — снимок один на дату **на пользователя**.

## Оценка

6–8 часов. Регистрация по инвайт-коду и тики по пользователям — не здесь.
