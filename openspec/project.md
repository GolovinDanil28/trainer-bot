# Контекст проекта

## Что это

**Trainer-bot** — Telegram-бот напоминаний о тренировках, который подстраивает
план под самочувствие пользователя.

Это **первый** из четырёх продуктов учебного хаба. Остальные (english,
python-trainer, ai-engineering) — в `~/.config/opencode/ПРОЕКТЫ.md` с
приоритетами и планом.

## Реестр продуктов

| Проект | Репозиторий | Статус |
|---|---|---|
| trainer-bot | `~/Projects/trainer-bot/` ← **этот** | активный |
| english | `~/Projects/english/` | запланирован |
| python-trainer | `~/Projects/python-trainer/` | запланирован |
| ai-engineering | `~/Projects/ai-engineering/` | параллельный трек |

## Правила проекта

Полные правила хаба — `~/.config/opencode/AGENTS.md`. Кратко:

1. Код — только после утверждённой OpenSpec-спеки.
2. Агент объясняет «почему», а не только «что».
3. Каждая существенная сессия заканчивается записью в
   `~/.config/opencode/learning/LOG.md`.
4. Требования должны быть проверяемы тестом.

Из локального — `AGENTS.md` в корне этого репозитория.

## Технический стек (решения хаба)

| Слой | Решение | Почему |
|---|---|---|
| Язык | Python 3.14 | один язык на все 4 продукта, минимум переключений |
| БД | SQLite | нулевая настройка, файл = вся база, легко мигрировать на Postgres |
| ORM | SQLAlchemy 2.0 | явные запросы, легко читать и учить |
| Бот | python-telegram-bot | проще для новичка, чем aiogram |
| Расписание | APScheduler | встроенный, персистентный |
| Тесты | pytest | стандарт де-факто |
| Локальный запуск | Docker Compose | окружение воспроизводимо |

Решения не высечены в камне: если в спеке обоснована замена — меняем в специ.

## Соглашения об именовании в спеках

- Capability (папка в `specs/`): `trainer-bot-<что>`, kebab-case.
- Change id: `<проект>-<что делаем>`, kebab-case.
- Требования нумеруются как `R-01`, `R-02` внутри спеки — на них ссылаются
  пункты `tasks.md`.
- Сценарии именуются по-русски, ключевые слова `WHEN`/`THEN` — по-английски.

## Частые грабли

- «Быстро», «удобно», «надёжно» — **не** требования. Проверяемость важнее
  красоты формулировки.
- Требование без сценария `WHEN`/`THEN` считается незакрытым.
- Пункт `tasks.md` без теста считается невыполненным.
- Правка кода при отсутствии открытой спеки блокируется guardrails-плагином
  (спросит, а не ошибётся).
