# Spec delta guard

Применяй **перед** `openspec archive`, после того как code-задачи закрыты.
Смысл: `openspec validate <change> --strict` проверяет дельту саму по себе, но
не замечает, что MODIFIED-блок написан поверх прошлой дельты и потерял
`AND`-условия из смерженной спеки. Так уже случилось с R-01.

## Шаги

1. Запусти механическую проверку:

   ```bash
   python scripts/spec_delta_guard.py <change-id>
   ```

   Скрипт для каждого `MODIFIED` требования сравнивает блок дельты с блоком
   в `openspec/specs/`:
   - все сценарии из смерженной спеки присутствуют в дельте;
   - ни одна строка `- **AND** …` не потеряна;
   - текст требования (до первого `#### Scenario:`) не длиннее 500 символов.

   Выход 1 — есть расхождения; 0 — чисто.

2. Если скрипт нашёл потерю — **не правь спеку руками на месте**. Вернись в
   дельту, скопируй блок из `openspec/specs/` целиком и внеси изменение поверх
   него. Иначе потеря повторится при следующем мерже.

3. Запусти полный гейт:

   ```bash
   ./scripts/check.sh
   ```

4. Только после этого — архивация. После архивации прогони `./scripts/check.sh`
   ещё раз: `validate --archived` проверяет задачи в архиве.

## Чего не делает скилл

- Не решает, какое поведение правильное: расхождение «спека слабее кода» —
  повод обновить спеку, а не удалить проверку.
- Не заменяет тесты. Если требование изменилось осознанно, сценарии правятся
  в дельте вместе с кодом.
