# Глоссарий

Термины, которые встречаются в этом хабе. Своими словами, чтобы было понятно,
когда читаешь.

## Процесс

**Change (изменение)** — одна спека на одну функциональность. Лежит в
`openspec/changes/<id>/`. Живёт, пока не заархивирована.

**Capability (возможность)** — группа требований к системе, которая существует
долго. Лежит в `openspec/specs/<capability>/spec.md`. Это «актуальная
правда» о том, как система ведёт себя.

**Delta-спека** — в `changes/<id>/specs/` лежит не вся правда о системе, а
только **разница** с текущей: `## ADDED Requirements`, `## MODIFIED
Requirements`, `## REMOVED Requirements`. При архивировании разница переносится
в основные спеки.

**Proposal** — зачем и что меняется. Ответ на «почему вообще», без деталей.

**Design** — как именно делаем: архитектура, альтернативы, риски.

**Tasks** — чек-лист реализации. Один пункт = 1–2 часа = один тест.

**Требование (requirement)** — проверяемое утверждение `SHALL` + сценарии
`WHEN`/`THEN`. Не «удобно», а «не позднее чем через 60 секунд после
наступления времени тренировки».

**Сценарий (scenario)** — конкретный случай: условие `WHEN` и ожидаемый
результат `THEN`. Из сценария получается тест.

## Инструменты

**OpenSpec** — фреймворк спецификаций. Держит требования и превращает их в
чек-лист задач. `/opsx-propose` → `/opsx-apply` → `/opsx-archive`.

**Harness (харнесс)** — обвязка вокруг модели: роли, инструменты, правила,
память, проверка. Подробно — `learning/HARNESS.md`.

**Skill (скилл)** — переиспользуемая процедура в `.opencode/skills/<id>/SKILL.md`.
Подгружается в контекст только когда релевантна.

**Agent (агент)** — именованный профиль: системный промпт + модель +
разрешения + режим (`primary` / `subagent`).

**Subagent** — дочерняя сессия. Родительский агент запускает, получает
результат, продолжает работу. Контекст не засоряется.

**Hook (хук)** — перехватчик в плагине: `permission.hook`,
`tool.hook`, `shell.hook`, `session.hook`. Превращает правило в механику.

**Permission (разрешение)** — правило «может ли агент сделать X с Y».
`allow` / `ask` / `deny`. Последнее совпавшее правило выигрывает.

**Policy (политика)** — жёсткий запрет. В отличие от разрешения, не спрашивает,
а блокирует, и обойти её нельзя.

**Instruction (инструкция)** — постоянный текст, который агент всегда видит.
В OpenCode V2 это `AGENTS.md` (только `AGENTS.md`, `CLAUDE.md` не читается).

**Command (команда)** — именованный шаблон промпта: `/teach`, `/retro`,
`/opsx-propose`.

## RAG и память

**RAG** — Retrieval-Augmented Generation: подгружать в контекст релевантные
куски базы знаний по запросу. В этом хабе — отложено осознанно, см.
`knowledge/rag/when-not-to-use.md`.

**Гибридный поиск** — сначала дешёвый и точный (`grep` по маркдауну), затем
дорогой (семантика по эмбеддингам), затем внешние источники.

**Контекстное окно** — сколько токенов модель держит «в голове» за раз.
Чистый контекст важнее умной модели.

## Прочее

**MCP** — протокол подключения внешних инструментов к агенту (Model Context
Protocol). Сервер отдаёт свои инструменты как обычные.

**Tool (инструмент)** — функция, которую агент может вызвать: `read`, `edit`,
`shell`, `webfetch`, `grep`.

**Compact (компакция)** — автоматическое сжатие истории сессии, когда
контекст переполняется. После компакции важные решения лучше держать в
спеках, а не в чате.
