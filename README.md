# Проект по умолчанию — учебный хаб

Четыре продукта строятся здесь одновременно, но главная цель хаба — **научить
работать с ИИ**, а не просто получить четыре готовых приложения.

Источник: срез сессии OpenCode Desktop от 19.10.2026.

## С чего начануть

1. Прочитать [`ПРОЕКТЫ.md`](ПРОЕКТЫ.md) — реестр четырёх треков.
2. Прочитать [`ROADMAP.md`](ROADMAP.md) — план на 12 недель.
3. Прочитать [`AGENTS.md`](AGENTS.md) — правила, которые агент соблюдает сам.

## Роли (агенты)

| Агент | Режим | Модель | Что делает |
|---|---|---|---|
| `tutor` | primary | `glm-5.3-flash-free` | объясняет, спрашивает, не делает за тебя |
| `planner` | subagent | `deepseek-v4.1-flash-free` | идея → спека OpenSpec |
| `implementer` | subagent | `minimax-m3.1-flash-free` | выполняет пункты `tasks.md` |
| `reviewer` | subagent | `deepseek-v4.1-flash-free` | ревью против спеки, только читает |
| `researcher` | subagent | `glm-5.3-flash-free` | поиск по базе знаний |

Все модели — **бесплатные** ($0/$0) в OpenCode Console. Подписка за $10 не
нужна для всего плана.

## Команды

| Команда | Что делает |
|---|---|
| `/spec <идея>` | создать спеку (proposal + requirements + design + tasks) |
| `/teach <тема>` | разобрать тему на материале твоих проектов |
| `/retro` | ретроспектива + запись в `learning/LOG.md` |
| `/status` | статус хаба: спеки, задачи, журнал, токены |
| `/opsx-propose` | официальная команда OpenSpec (спека целиком) |
| `/opsx-apply` | официальная реализация по `tasks.md` |
| `/opsx-archive` | архивировать закрытую спеку |
| `/opsx-explore` | «думающий партнёр» до написания спеки |
| `/opsx-update` | пересобрать артефакты спеки после правок |
| `/opsx-sync` | перенести delta-спеки в основные `specs/` |

## Скиллы (свои)

| Скилл | Когда применяется |
|---|---|
| `learn-by-doing` | пользователь хочет разобраться, а не получить ответ |
| `spec-first` | перед любой реализацией функциональности |
| `socratic-debug` | когда застрял с ошибкой |

## Хуки (guardrails)

| Хук | Что делает |
|---|---|
| `permission.hook("evaluate")` × 2 | spec-gate: правка `projects/**` без открытой спеки → спросить; опасные shell-команды → запретить |
| `tool.hook("execute.after")` | аудит: каждое изменение файла → `.hub/audit.jsonl` |
| `session.hook("prompt")` | подсказка: просишь реализовать, а спеки нет → напоминание в промпте |
| `shell.hook("create.before")` | потолок таймаута shell-команды |

## Принципы

1. **Код — только после утверждённой спеки.** Не «у нас есть тесты», а «у нас
   есть требования, которые можно проверить».
2. **Агент объясняет «почему».** Ценность не в коде, а в том, что ты после
   этого понимаешь, как такие вещи делаются.
3. **Каждая сессия оставляет след.** `learning/LOG.md` — не отчёт об агенте, а
   запись о твоём понимании.
4. **Харнесс вместо магии.** Правило, которое нельзя нарушить, должно быть
   в коде (хуком), а не в голове.
