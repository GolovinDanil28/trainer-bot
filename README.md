# Trainer-bot — Telegram-напоминалка

Активный проект. Цель — MVP, который ты реально используешь две недели подряд.

Это **единственный** репозиторий на текущем этапе: в нём и продукт, и учебная
обвязка (правила, агенты, спеки, журнал). Остальные треки из `ПРОЕКТЫ.md` позже
получат собственные репозитории.

## Что это

Бот, который:
- напоминает о тренировках по расписанию;
- фиксирует, что выполнено, а что пропущено;
- вечером спрашивает про самочувствие (1–5);
- на основе самочувствия и истории корректирует план на завтра.

Ключевая ценность — **третий и четвёртый пункты**. Напоминания без адаптации
делает любой календарь. Бот, который подстраивает нагрузку, — нет.

## Стек

| Слой | Решение |
|---|---|
| Язык | Python 3.14 |
| Бот | python-telegram-bot |
| БД | SQLite + SQLAlchemy 2.0 |
| Расписание | APScheduler |
| Тесты | pytest |
| Локальный запуск | Docker Compose |

Решения фиксируются в спеке (`openspec/changes/trainer-bot-*/design.md`), а не
здесь — здесь только указатель.

**Ключевое архитектурное решение:** доменная логика не знает про Telegram.
`core/` не импортирует `bot/` — иначе тестировать логику без Telegram будет
мучительно, а именно её и надо тестировать.

## Роли (агенты)

| Агент | Режим | Модель | Что делает |
|---|---|---|---|
| `tutor` | primary | `glm-5.3-flash-free` | объясняет, спрашивает, не делает за тебя |
| `planner` | subagent | `deepseek-v4.1-flash-free` | идея → спека OpenSpec |
| `implementer` | subagent | `minimax-m3.1-flash-free` | выполняет пункты `tasks.md` |
| `reviewer` | subagent | `deepseek-v4.1-flash-free` | ревью против спеки, только читает |
| `researcher` | subagent | `glm-5.3-flash-free` | поиск по базе знаний |

Все модели — **бесплатные** ($0/$0) в OpenCode Console.

## Хуки (guardrails)

| Хук | Что делает |
|---|---|
| `permission.hook("evaluate")` × 2 | spec-gate: правка `src/**` или `tests/**` без открытой спеки → спросить; опасные shell-команды → запретить |
| `tool.hook("execute.after")` | аудит: каждое изменение файла → `.hub/audit.jsonl` |
| `session.hook("prompt")` | подсказка: просишь реализовать, а спеки нет → напоминание в промпте |
| `shell.hook("create.before")` | потолок таймаута shell-команды |

## Как работать с проектом

```bash
cd ~/Projects/trainer-bot

# 1. Спека
/opsx-propose "MVP тренера-напоминалки"

# 2. Утвердить спеку (посмотреть proposal.md, specs/, tasks.md)

/review

# 5. Архив
/opsx-archive
```

Правки кода без открытой спеки блокирует guardrails-плагин (спросит, а не
упадёт).

## Диагностика харнесса

Плагин `guardrails` пишет два файла в `.hub/` (папка в `.gitignore`):

| Файл | Что там |
|---|---|
| `.hub/audit.jsonl` | каждое изменение файла: время, инструмент, путь, id сессии |
| `.hub/debug.log` | срабатывания хуков: `spec-gate СРАБОТАЛ …`, `shell-guard СРАБОТАЛ …` |

Это **учебный инструмент**: открывай `debug.log` после сессии и смотри, какие
правила реально сработали, а какие живут только в тексте `AGENTS.md`. Правило,
которое ни разу не сработало, — это неправило.

Проверить, что защита жива:

```bash
dd if=/dev/zero of=/dev/null     # должно быть заблокировано shell-guard
```

## Принципы

1. **Код — только после утверждённой спеки.** Не «у нас есть тесты», а «у нас
   есть требования, которые можно проверить».
2. **Агент объясняет «почему».** Ценность не в коде, а в том, что ты после
   этого понимаешь, как такие вещи делаются.
3. **Каждая сессия оставляет след.** `learning/LOG.md` — не отчёт об агенте, а
   запись о твоём понимании.
4. **Харнесс вместо магии.** Правило, которое нельзя нарушить, должно быть
   в коде (хуком), а не в голове.
