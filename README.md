# Trainer-bot

Telegram-бот, который напоминает о тренировках и подстраивает план под
самочувствие.

## Зачем

Напоминание в нужное время умеет любой календарь. Ценность этого бота — в
адаптации: вечером он спрашивает самочувствие по шкале 1–5 и с его учётом, а
также с учётом истории выполнения, меняет план на следующий день. Не «ещё один
трекер», а тренер, который замечает, что ты не выспался.

## Что делает (v1)

- хранит недельное расписание тренировок, задаваемое командами в Telegram;
- в нужное время отправляет напоминание с кнопками «сделал» / «пропустил»;
- ведёт журнал выполнения: что сделано, что пропущено, где не было ответа;
- вечером спрашивает самочувствие по шкале 1–5 и показывает план на завтра.

## Как пользоваться

`/start` и `/help` присылают карточку возможностей; те же слова работают как
фраза: «помоги», «помощь», «help», «инструкция», «что ты умеешь», «как
пользоваться», «какие команды». Справка не обращается к модели, поэтому работает
и без Ollama.

| Команда | Что делает | Пример |
|---|---|---|
| `/start` | приветствие и справка | `/start` |
| `/help` | справка | `/help` |
| `/new` | создать тренировку | `/new силовая Пн,Ср,Пт 19:30` |
| `/list` | показать расписание | `/list` |
| `/off` | отключить тренировку | `/off 2` |
| `/history` | последние отметки | `/history` |
| `/wellness` | самочувствие за сегодня | `/wellness 3 не выспался` |
| `/plan` | план на завтра | `/plan` |
| `/week` | разбор недели: сколько сделано, что мешало, что менять | `/week` |

Можно фразой:

```
силовая пн ср пт в 19:30                        → /new силовая Пн,Ср,Пт 19:30
бег по вторникам и четвергам в восемь утра      → /new бег Вт,Чт 08:00
покажи расписание                                → /list
убери вторую тренировку                          → /off 2
```

Чего не умеет: разовые переносы, замену одной тренировки другой, несколько
действий в одной фразе, составление плана на следующую неделю.

## Обычный текст

Необязательно помнить синтаксис: бот понимает фразу про недельное расписание и
выполняет те же операции, что строгие команды.

- **Понимает:** создать недельную тренировку (тип + дни + точное время) или
  разовую на дату («бег 7 км завтра в 19:00»), показать список, отключить
  тренировку по номеру из расписания.
- **Чего не понимает:** список ограничений — в разделе «Как пользоваться» и в
  карточке `/help`. На незнакомое бот отвечает подсказкой и ничего не меняет.
- **Без Ollama:** бот запускается, строгие команды работают; на свободный текст
  он отвечает подсказкой. Модель локальная (`qwen2.5:7b` по умолчанию), текст не
  уходит в облако.
- **Известное ограничение:** «половина седьмого вечера» может распознаться как
  17:30 или 19:30. Ответ всегда показывает распознанное время — ошибку видно
  сразу и правится через `/off` + `/new`.

## Самочувствие и план

Вечером (по умолчанию в 21:00, время меняется через `WELLNESS_TIME`) бот
спрашивает самочувствие и показывает план на завтра. Оценку можно поставить
кнопкой, командой `/wellness 3` или с заметкой: `/wellness 2 не выспался`.

Правила v1 — три ступени, без ML:

| Оценка | Что в плане |
|---|---|
| 1–2 | отдых |
| 3 | тренировки на 70 % длительности (вниз до 5 минут, не меньше 5) |
| 4–5 | тренировки как в расписании |

**План — это рекомендация, а не отмена.** Расписание и напоминания он не
меняет: при отдыхе напоминание всё равно придёт, и его надо отметить
«пропустил», чтобы день попал в журнал. Автоматическая отмена — отдельное
изменение, которого в v1 нет.

## Чего в v1 осознанно нет

- несколько пользователей (MVP на одного);
- веб-интерфейс;
- ML-адаптация: план меняется по правилам, потому что правила можно объяснить
  и отладить;
- медицинские данные: самочувствие — это число 1–5 и свободный текст.

## Как устроено

Четыре принципа, которые определяют всю архитектуру:

1. **Домен не знает про Telegram.** `core/` описывает тренировки, расписание и
   правила; `bot/` умеет только разговаривать. Логику можно тестировать без сети.
2. **Время хранится в UTC, показывается в таймзоне пользователя.** Иначе переход
   на летнее время сдвигает все напоминания на час.
3. **Напоминание не уходит дважды.** Уникальность пары «тренировка + момент»
   держит база, а не память процесса: рестарт бота ничего не дублирует.
4. **Сначала спецификация, потом код.** Поведение описано в `openspec/` как
   требования со сценариями; каждая задача реализуется вместе с тестом.

## Стек

| Слой | Решение |
|---|---|
| Язык | Python 3.14 |
| Бот | python-telegram-bot |
| БД | SQLite + SQLAlchemy 2.x |
| Расписание | APScheduler |
| Конфигурация | pydantic-settings |
| Тесты и линт | pytest, ruff |

Технические решения и их альтернативы фиксируются в `design.md` конкретного
изменения, а не здесь.

## Структура репозитория

```
trainer-bot/
├── AGENTS.md              # правила работы над проектом
├── README.md              # этот файл
├── opencode.json          # разрешения и политики агента
│
├── openspec/              # спецификации
│   ├── project.md         # контекст проекта: стек, соглашения, грабли
│   ├── specs/             # утверждённые требования
│   └── changes/           # незакрытые изменения
│
├── src/
│   ├── core/              # домен: расписание, правила, форматирование
│   ├── db/                # модели и сессии
│   ├── bot/               # хендлеры Telegram
│   └── scheduler/         # когда наступило время
│
├── tests/
├── knowledge/             # база знаний
└── learning/              # журнал обучения
```
