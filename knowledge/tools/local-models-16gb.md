# Что можно запускать локально на 16 GB RAM

**Вопрос, на который отвечает эта заметка:**
Какие локальные модели через Ollama реально работают на этой машине?

**Ответ:**

Машина: Apple M5 (M5 — 10 ядер CPU + GPU), 16 GB RAM (единая память, доступна
и CPU, и GPU), 224 GB свободного диска. Ollama-клиент 0.30.7 установлен,
сервер не запущен.

Ориентир по объёму модели (Q4_K_M):

| Размер | RAM на модель | Вердикт |
|---|---|---|
| 3–4B | ~2.5–3.5 GB | ✅ легко, быстро, можно две одновременно |
| 7–8B | ~5–6.5 GB | ✅ рабочий вариант для ассистента/суммаризации |
| 12–14B | ~9–11 GB | ⚠️ влезает, но мало запаса для контекста |
| 30–32B | ~20+ GB | ❌ не влезает, будет swap |
| 70B | ❌ | ❌ только на удалённой машине |

Три практических вывода:

1. **Локально реально только 7–8B** (qwen3:8b, llama3.1:8b, gemma3:8b).
   Для задач «пересказать/классифицировать/ответить по базе» этого хватает.
2. **Для кода локальная модель слабее облачной** — на M5 без оптимизированного
   ядра скорость на 14B упадёт до единиц токенов/с. Как основной инструмент
   разработки — не подходит.
3. **Локальная модель полезна как приватный помощник**: обработка личных
   данных тренировок (здоровье!) без отправки в облако. Для trainer-bot это
   отдельный сильный аргумент.

**Лайфхак для шифрования:** RAM на 16 GB — это ещё и проблема приватности,
если модель работает на твоих личных данных. Обфускация имён и отсутствие
истории запросов в облаке часто важнее качества модели.

## Пример

Для тренера по тренировкам: чувствительные данные (самочувствие, вес,
медицинские ограничения) → локальная модель 7–8B или вообще без LLM
(решается правилами). LLM нужен не для хранения, а для формулировки
напоминаний — а это можно сделать шаблонами.

## Почему это важно

Трек «AI Engineering» включает работу с локальными моделями. Прежде чем
качать 30B-модель и ждать 40 минут её загрузки, полезно знать потолок
машины.
